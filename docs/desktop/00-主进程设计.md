## 2. 启动时序（main/index.ts）

```
app.whenReady
  1. 注册 ipc 通道
  2. nativeTheme.themeSource = 'dark'（Windows 原生标题栏与深色 UI 一致）
  3. 创建主窗口（默认 1280×800，min 1024×680，contextIsolation: true，nodeIntegration: false，
     外部链接 setWindowOpenHandler → 系统浏览器）
  4. 加载页面：dev 用 VITE_DEV_SERVER_URL（固定端口 5180）；prod 加载 dist/index.html
  5. 创建 ServiceManager 并 start()
  6. 生命周期钩子：window-all-closed → stop；before-quit → 优雅退出
```

## 3. IPC 层（ipc.ts + preload.ts）

**主进程通道**（唯一登记处，新增通道必须在此）：

| 通道 | 方向 | 行为 |
|------|------|------|
| `rpc` (invoke) | R→M | 参数 `(method, params)`；method 必须在 `METHOD_NAMES` 白名单内，否则拒绝；转交 `service-manager.rpc()` |
| `app:version` (invoke) | R→M | 返回 `app.getVersion()` |
| `service:restart` (invoke) | R→M | 触发 ServiceManager 重启 Python（侧边栏重启按钮） |
| `service:event` (send) | M→R | 转发 Python 通知（progress.update / log.append / …）与主进程服务状态变更 |

**preload 暴露的 API 形状**（渲染层唯一入口）：

```ts
window.dramaclip = {
  rpc(method: string, params?: object): Promise<unknown>;
  appVersion(): Promise<string>;
  restartService(): Promise<void>;          // service:restart
  onServiceEvent(cb: (event: ServiceEvent) => void): () => void;  // 返回取消订阅
};
```

## 4. pipe-server（套接字服务端）

```ts
interface PipeServer {
  readonly address: string;             // host:port（listening 后有效）
  call(method: string, params: object, timeoutMs?: number): Promise<unknown>; // 默认 30s 超时
  send(obj: unknown): void;            // 主动下行（预留）
  close(): Promise<void>;
}
```

行为要点：
- 传输：`127.0.0.1:0` 环回 TCP（ADR-002 修订版；端口由系统随机分配）；
- **单连接**：新连接到达时旧连接销毁；未通过 hello 认证的连接 10s 后销毁；
- hello 校验 token（来自 spawn env）→ 回 `hello-ack` → 标记就绪并通知 service-manager；
- request 按 id 关联 response；超时 Promise reject（不取消对端执行）；
- 收到 notification → 回调上抛；
- 单行 > 16MB 视为协议错误，断开连接。

## 5. restart-policy（重启策略状态机，纯逻辑）

```ts
class RestartPolicy {
  onFailure(): { action: 'restart' | 'give-up'; delayMs: number };
  recordStableRun(durationMs: number): void;  // 稳定运行达标后清零计数
}
```

参数：最大重启 3 次；退避 2s / 4s / 6s；稳定运行 ≥ 60s 清零。

## 6. service-manager（Python 进程管理）

**解释器解析**：

| 模式 | 命令 | 参数 |
|------|------|------|
| dev（!app.isPackaged） | 仓库 `.venv` 解释器，不存在则 PATH `python` | `['-m', 'dramaclip']` |
| prod | `resources/dramaclip-service.exe`（sidecar，P2） | `[]` |

**spawn 环境**：`DRAMACLIP_SERVICE_ADDRESS`（127.0.0.1:port，pipe-server 监听后分配）/ `DRAMACLIP_AUTH_TOKEN`（64 hex 随机）/ `DRAMACLIP_DATA_DIR`（dev=仓库 `data/`，prod=`%APPDATA%/DramaClip`）+ `PYTHONUNBUFFERED=1`（stdout 崩溃日志不缓冲）。

**状态机**：

```
starting ──hello 通过──▶ ready
   │ hello 10s 超时        │ 心跳：5s ping，连续 3 次失败 / 进程退出
   │                      ▼
   └──────▶ restarting ◀─┘ ──restart-policy──▶ unavailable（3 次耗尽，通知 UI）
                  │ 稳定运行 60s
                  ▼
               ready（计数清零）
```

- 每次状态变更与 Python 通知都经 `service:event` 下发渲染层；
- `stop()`：发 `system.shutdown` → 3s 超时 kill → 关闭 pipe-server。

## 9. 激活凭证、心跳与强制重授权

- 凭证存储：`main/services/activation-store.ts` 用 Electron `safeStorage` 加密后写 `userData/activation.json`（0600，原子替换）。字段含网关地址、激活码、设备令牌/令牌 id、套餐、到期、最近校验、设备标签；`deactivated`（`{reason, at}`）表示上次发现授权无效、令牌已清空，重启后据此继续整屏阻断而不是退回“从未激活”。
- 心跳状态机：`main/services/activation-heartbeat.ts` 维护 `inactive → verifying → active ⇄ suspended(network)`，授权无效时进入 `reactivation_required(reason)`。默认每 5 分钟（±10% 抖动）请求一次 `/v1/me`，网络失败按 1→2→5 分钟退避；进入 `reactivation_required` 即清定时器且不再安排心跳。
- 401 分流：`token_superseded` → 顶号（不重兑换）；`token_revoked` → 管理员吊销（不重兑换）；`invalid_token` 仅在“本会话未兑换过 + 距上次兑换 ≥10 分钟”守卫内自动重兑换一次；兑换后 60 秒内再 401 按顶号处理。403 停用/到期分别映射 `disabled`/`expired`。以上授权无效全部进入强制重授权，只有网络/超时/5xx 留在 `suspended(network)`。
- 唯一落盘点：`ActivationService` 订阅心跳 `onChange`，快照进入 `reactivation_required` 且记录仍有令牌时调用 `forceReactivation(reason)`：停表 → 清内存/磁盘令牌（保留脱敏激活码）→ 写 `deactivated` → 仅当 `llm.base_url` 仍指向本网关且 `llm.model='default'` 时清 `llm.api_key`（不删 base_url/model，便于重新激活覆盖）→ 发快照。`start()` 读到 `deactivated` 时直接进入强制态，不发任何网络请求；`status(true)` 在该状态同样跳过校验。
- 重新激活：`redeem()` 走完整兑换流程并覆盖为新记录，自然清除 `deactivated`；`unbind()` 删除凭证并整体清除强制态。清 token 失败或写盘失败只记日志，状态仍停在阻断，下一次心跳会重试落盘。
- 托管设置仍由激活写入 7 键（LLM 三键 + `asr.engine/model/base_url/api_key`）；清理/回滚规则见 `activation-service.ts` 注释与 D6/D14。
